# MediaTek на TECNO SPARK 40C (KM4k) — риски и что с ними делать

Телефон построен на MediaTek Helio G81 (MT6768), стоковая прошивка — HiOS 15.1.2 поверх Android 15.
GSI меняет только систему; **vendor, ядро, HAL-ы и прошивка модема остаются от HiOS**. Отсюда основные проблемы.

Проверить фактическое состояние: `./scripts/mt-fixes.sh --diagnose`.

---

## 1. Отпечаток — самый вероятный отказ

**Почему ломается.** Fingerprint HAL от MediaTek живёт в `vendor` и общается с датчиком через проприетарный
транспорт. В GSI на месте HAL-а стоит системный, а вендорный сервис отпечатка часто не регистрируется
вовсе: `dumpsys fingerprint` пуст, а в настройках пункт «Отпечаток» не появляется.

**Что пробовать (по порядку):**

| Действие | Как | Комментарий |
|---|---|---|
| «Виртуальные датчики как настоящие» | `persist.sys.phh.virtual_sensors_are_real=1` | В GSI нет treble_app — свойство ставится вручную; в LineageOS-GSI эквивалент — этот же `persist.*` |
| Отключить qfp-режим | `persist.qfp=false` | Снимает конфликт имён HAL-ов |
| Позиция датчика | `ro.fpsensor.position=1` | Это `ro.*`-свойство: **в живую систему не выставится**, только при сборке образа |
| Проверить регистрацию HAL | `adb shell lshal \| grep -i fingerprint` | Пусто → HAL не поднялся, дальше нужен патч образа |
| Проверить сервис | `adb shell dumpsys fingerprint` | Пусто → сервис отпечатка не отвечает |

**Честная оценка.** На MediaTek-GSI отпечаток заработал у части пользователей, у части — нет.
В BlueOS GSI v0.8.1 отдельных исправлений под MTK нет (автор проверял только Pixel 6a). Если отпечаток
не поднялся — самый надёжный путь: **путь C (свой порт LineageOS под KM4k)**, где вендорный fingerprint HAL
подключается родным `android.hardware.fingerprint-service.mediatek` (в `mt6768.mk` он уже есть).

---

## 2. Камера

**Почему ломается.** У TECNO камера реализована на MediaTek HAL3 с проприетарными расширениями. В GSI
системная часть HAL3 — AOSP-овская; вендорный `vendor/bin/hw/android.hardware.camera.provider@2.7-service_*`
может не подняться из-за несовпадения интерфейсов или отсутствия библиотек.

**Что пробовать:**

| Действие | Как |
|---|---|
| Включить HAL3 в системной части | `persist.camera.HAL3.enabled=1` |
| Включить HAL3 в vendor-части | `persist.vendor.camera.HAL3.enabled=1` |
| Включить EIS | `persist.vendor.camera.eis.enabled=1` |
| Посмотреть, что вообще видно | `adb shell dumpsys media.camera \| head -40` |
| Список provider'ов | `adb shell pm list features \| grep camera` |

Первые три — штатный фикс «камера молчит на GSI» из XDA-гайдов; вендорный HAL читает
`persist.vendor.camera.HAL3.enabled`, системный — `persist.camera.HAL3.enabled`, поэтому ставятся оба.

**Как выглядит поломка.** Камера не открывается (чёрный экран, «Камера не отвечает»), либо открывается,
но без картинки, либо только фронтальная.

**Что делать, если не помогло.** В `mt6768.mk` (общее дерево MT6768 в LineageOS) камера подключается через
prebuilt-файлы `android.hardware.camera.front/full/flash-autofocus.xml` и `audio.primary.default` —
то есть в полном порте используются **стоковые** MTK-HAL-ы из `vendor` (они вытаскиваются
`extract-files.py` с телефона). То есть камера в пути C — шанс, в пути A/B — нет.

## 3. Звук

**Почему ломается.** Аудио-тракт MediaTek (offload, dolby, mic) сильно завязан на вендорные библиотеки.
Сами `audio.primary.default` и `audio_policy.stub` из `mt6768.mk` рассчитаны как раз на GSI-подобную сборку,
поэтому базовый звук обычно работает.

**Проверка:**
```
adb shell dumpsys media.audio_flinger | head -40
adb shell dumpsys audio | grep -iE "STREAM_MUSIC|ringer"
```

**Типичные симптомы:** звук в приложениях есть, а звонки идут без звука (не поднялся `MtkInCallService`),
или наоборот — тихо на разговорном динамике.

**Что делать:** если не работают звонки — проверьте IMS: `dumpsys ims` / `dumpsys telephony.registry`.
Для IMS в общем дереве MT6768 есть каталог `blob-patches/` (0001-0022) — патчи поверх вендорских IMS-блобов,
их нужно применить при сборе блобов (путь C).

---

## 4. Яркость, HBM, дисплей

**Почему ломается.** Подсветка на MTK управляется через vendor-HAL и проприетарные sysprop (`ro.panel.*`,
`persist.sys.display.*`). Яркость может «залипать» на максимуме, не работать авто-яркость или отсутствовать
ночной режим.

**Что делать:**
* Проверить: `adb shell settings get system screen_brightness_mode`, `adb shell dumpsys display | grep -i brightness`.
* Если яркость не управляется — это почти всегда значит, что не поднялся вендорный `composer/display` HAL;
  в пути C он подключается из блобов TECNO.

---

## 5. SIM, сеть, звонки

Обычно работают: модем и RIL остаются вендорными, а системная часть Treble-совместима.
Проверка: `adb shell dumpsys telephony.registry | head -30`, `adb shell getprop | grep -i ril`.
Если SIM не видно — проверьте `ro.ril.*` и `gsm.*` свойства.

---

## 6. Wi-Fi, Bluetooth

Обычно работают: драйверы и стек вендорные, системная часть — из GSI.
Проверка: `adb shell dumpsys wifi | head -20`, `adb shell dumpsys bluetooth_manager | head -20`.
Wi-Fi на MT6768 — `wlan_drv_gen4m_6768.ko` + `wmt_drv.ko`/`wmt_chrdev_wifi.ko` (см. `BoardConfig.mk` дерева
`motorola_lamu`) — в GSI они приходят из вендора телефона, то есть работать должны.

---

## 7. Датчики (акселерометр, гироскоп, датчик приближения)

**Почему ломается.** Виртуальные датчики (акселерометр/гироскоп для поворота экрана) в GSI эмулируются.
Если система считает их «ненастоящими», приложения (в том числе автоповорот и некоторые банковские)
не доверяют показаниям.

**Что делать:** `persist.sys.phh.virtual_sensors_are_real=1` — как раз этот флаг.

---

## Сводка: что чинится вживую, а что — только в образе

| Свойство | Тип | Меняется на живой системе? |
|---|---|---|
| `persist.sys.phh.virtual_sensors_are_real` | persist | да (`setprop`) |
| `persist.qfp` | persist | да |
| `persist.camera.HAL3.enabled` | persist | да |
| `persist.vendor.camera.fd` | persist | да |
| `ro.fpsensor.position` | ro | **нет** — только при сборке образа |
| `ro.vndk.version` и прочие `ro.*` | ro | **нет** |

Вывод: если отпечаток не поднялся из-за `ro.fpsensor.position`, путь A не поможет — нужен путь B
(собрать свой GSI с этим свойством) или путь C.

## Итоговая оценка для KM4k

| Подсистема | Прогноз на GSI | Путь C (свой порт) |
|---|---|---|
| Загрузка и базовая система | высокий шанс | почти наверняка |
| Интернет, Wi-Fi, Bluetooth | высокий | высокий |
| Звук (приложения) | средний-высокий | высокий |
| Камера | низкий-средний | средний-высокий (нужны блобы TECNO) |
| Отпечаток | низкий | средний-высокий |
| Звонки/IMS | средний | средний |
| Яркость | средний | высокий |
