# Откат: как вернуть стоковую прошивку TECNO SPARK 40C

Цель документа — чтобы откат был возможен в любой момент и не превращался в кирпич.

---

## 0. Главное правило

> **Никогда не выполняйте `fastboot flashing lock`, пока на телефоне стоит GSI/BlueOS.**

Причина: стоковая HiOS и GSI подписаны разными ключами. Загрузчик, закрытый на стоковом ключе, требует
подпись, которой у образа GSI нет — телефон просто не загрузится («no valid slot» / чёрный экран).
Восстановление после этого возможно только через полное восстановление заводской прошивки (раздел 4).

---

## 1. Мягкий откат: вернуться в HiOS, оставив GSI на месте

Это **первый** способ: он ничего не удаляет и обратим.

**Способ 1 — обычная перезагрузка.**
DSU по умолчанию стартует гостевую систему **один раз**: если GSI включили и загрузились, то следующая
перезагрузка вернёт в стоковую HiOS. Просто перезагрузитесь:

```
adb reboot
```

**Способ 2 — кнопка в уведомлении DSU.**
В шторке есть постоянное уведомление «Dynamic System Updates» с кнопками **Restart** (войти в GSI)
и **Discard** (удалить образ).

**Способ 3 — gsi_tool.**
```
adb shell gsi_tool disable   # липкий режим выключить: следующая загрузка — сток
adb shell gsi_tool status    # посмотреть состояние: installed / running / enabled / normal
adb shell gsi_tool enable    # включить обратно
adb shell gsi_tool enable -s # только на одну загрузку
```
`gsi_tool` живёт в `system/gsid` (в LineageOS/AOSP-GSI он есть; в стоковой HiOS может отсутствовать —
тогда пользуйтесь способами 1 и 2).

Готовый скрипт: `./scripts/rollback-dsu.sh {status|disable|enable|wipe|wipe-data}`.

---

## 2. Удалить образ GSI

**Через уведомление.** Кнопка **Discard** в уведомлении DSU — самый простой путь: образ и его данные удаляются.

**Через gsi_tool (нужен доступ к gsid):**
```
adb shell gsi_tool wipe        # удалить образ GSI и его данные
adb shell gsi_tool wipe-data   # стереть только userdata гостевой системы
```
`wipe-data` нельзя выполнять, находясь внутри работающего GSI, — сначала выйдите в сток.

**Вручную (если ничего не работает).** Раздел GSI создаётся в супер-разделе; его слот — `gsi/dsu/<имя>`.
Список слотов показывает `gsi_tool status` (при root). Полная очистка — `fastboot flashing lock` **не делать**;
если образ «залип», помогает `fastboot -w` (сотрёт данные, но вернёт стоковую систему).

---

## 3. Если GSI не грузится, а стоковая система работает

1. `adb reboot` — попробовать обычную перезагрузку.
2. `adb shell gsi_tool disable` — снять липкий режим.
3. `adb shell gsi_tool wipe` — удалить образ.
4. Крайний случай: `adb shell am start-activity -n com.android.dynsystem/com.android.dynsystem.VerificationActivity`
   не поможет — это установщик. Вместо этого: `fastboot -w` из fastboot-режима (стирает данные, GSI-раздел
   перестаёт использоваться).

---

## 4. Вернуть стоковую прошивку TECNO

У TECNO нет официального `flash.android.com` (это инструмент Google для Pixel). Варианты:

1. **SP Flash Tool (Windows)** — официальный путь Transsion:
   * скачать прошивку **именно для KM4k** (TECNO SPARK 40C) с сайта TECNO или из trusted-источников;
   * разблокировать загрузчик на телефоне (снова: Tecno ID + 14 дней);
   * SP Flash Tool → `Download` → выбрать прошивку → `Download` (формат) → `Go`;
   * в поле `Preloader` выбрать файл из прошивки, если он требуется.
2. **Восстановление через fastboot** (если прошивка в формате fastboot):
   ```
   adb reboot bootloader
   fastboot flash system system.img
   fastboot flash vendor vendor.img
   fastboot -w
   fastboot reboot
   ```
   Точный состав разделов зависит от прошивки; универсального набора для TECNO нет.
3. **Сервисный центр TECNO** — если загрузчик заблокирован или система не грузится совсем.

> Перед любым из этих шагов: **сохраните данные**, если это ещё возможно, и запишите точные названия разделов
> из `fastboot getvar all` — иначе легко прошить не то.

## 5. Что стирается, а что нет

| Действие | `/data` (фото, приложения) | Система | Загрузчик |
|---|---|---|---|
| `adb reboot` из GSI | целы | стоковая | разблокирован |
| `gsi_tool disable` | целы | стоковая | разблокирован |
| `gsi_tool wipe` | целы (стираются только данные GSI) | стоковая | разблокирован |
| `fastboot flashing lock` (после полного снятия GSI) | целы | стоковая | **заблокирован** |
| `fastboot flash system` | стираются | новая | разблокирован |
| `fastboot -w` | стираются | стоковая | разблокирован |
| SP Flash Tool (формат) | стираются | стоковая | разблокирован |

---

## 6. Чек-лист после отката

```
adb shell getprop ro.build.display.id          # должно быть HiOS-овское значение
adb shell getprop ro.boot.flash.locked         # 0 = разблокирован, 1 = заблокирован
adb shell getprop ro.product.model             # TECNO KM4k
```

Если `ro.build.display.id` показывает `GSI on ARM64` — вы всё ещё в гостевой системе: выполните
`./scripts/rollback-dsu.sh disable` и перезагрузитесь.

---

## 7. Возврат стоковой прошивки, если телефон не грузится совсем

1. Зажать питание + громкость вниз → recovery.
2. Если recovery стоковый: `adb sideload` не подходит (нужен подписанный пакет) — проще SP Flash Tool.
3. Если recovery BlueOS: он умеет «Apply from ADB», но пакет должен быть подписан тем же ключом, что и сборка
   (готовые обновления с Releases BlueOS). Для полного восстановления — SP Flash Tool.
4. Телефон в бесконечной загрузке (bootloop): питание + громкость вниз → fastboot → `fastboot -w` → `fastboot reboot`.

---

## 8. Модель угроз: чего НЕ делать

* `fastboot flashing lock` при установленном GSI — кирпич.
* `fastboot flash vbmeta` стоковым `vbmeta.img` поверх GSI без сброса данных — система перестанет
  загружаться (проверка verity не пройдёт).
* `fastboot erase userdata` без нужды — просто стирает данные.
* Установка поверх GSI «обычного» LineageOS-зипа, подписанного другим ключом, — sideload откажется
  (понижение версии и чужая подпись). Сначала снимите GSI, потом ставьте.
