# Виджеты и сетка рабочего стола BlueOS под экран TECNO SPARK 40C (720×1600)

BlueOS заточен под Pixel 6a: экран 1080×2400, 420 dpi → **411×914 dp**, сетка рабочего стола **4×5**.
На TECNO SPARK 40C: 720×1600, 263 ppi, системная плотность Android обычно **320 dpi (xhdpi)** →
**360×800 dp**. Экраны разной высоты и ширины в dp, поэтому часть виджетов на KM4k получит
другую раскладку, чем на Pixel 6a. Ниже — расчёт и что с этим делать.

---

## 1. Исходные данные

| | Pixel 6a (эталон BlueOS) | TECNO SPARK 40C |
|---|---|---|
| Разрешение | 1080×2400 | 720×1600 |
| Плотность | 420 dpi | 320 dpi (проверить на телефоне) |
| Размер в dp | 411×914 | **360×800** |
| Сетка по умолчанию | 4×5 (жёстко задана патчем) | 4×5 (тот же патч) |

**Проверить плотность на телефоне (точнее, чем доверять таблице):**
```
adb shell wm density
adb shell wm size
```
Пересчёт: `dp = px × 160 / density`. При `density=320`: 720×1600/320×160 → 360×800 dp.

**Важно:** если после установки GSI плотность окажется другой (например, 240 dpi из-за `TARGET_SCREEN_DENSITY`
в дереве устройства), пересчитайте всё заново — расхождение в 20 % меняет все пороги.

---

## 2. Как BlueOS выбирает макет виджета

Механизм — `RemoteViews(Map<SizeF, RemoteViews>)`: Android сравнивает **фактический размер виджета в dp**
с порогами `SizeF(...)` и берёт ближайший подходящий макет. Пороги живут в файлах:

```
frameworks/base/packages/SystemUI/src/com/android/systemui/blueos/widgets/
    BlueOSBatteryWidgetProvider.kt
    BlueOSMediaWidgetProvider.kt
    BlueOSSummaryWidgetProvider.kt
    BlueOSTogglesWidgetProvider.kt
```

В пороги **входит внешний отступ виджета 8 dp** — то есть реальный размер макета на 8 dp меньше порога.
Это важно: порог `SizeF(110f, 40f)` — это макет 102×32 dp плюс отступы.

### Итоговые пороги (после всех патчей BlueOS 0.8.1)

| Виджет | Размер в dp | Макет | Комментарий |
|---|---|---|---|
| **Батарея** | 40×40 | `blueos_battery_widget_small` | 1×1, кольцо 56 dp |
| | 110×40 | `blueos_battery_widget_medium` | 2×1 |
| | 110×160 | `blueos_battery_widget_large` | 2×2 (порог поднят с 120 в патче 0019) |
| **Музыка** | 110×40 | `blueos_media_widget_small` | 2×1 |
| | 110×110 | `blueos_media_widget_square` | 2×2 |
| | 300×40 | `blueos_media_widget_wide` | широкая полоса (порог поднят с 220 в патче 0019) |
| | 300×160 | `blueos_media_widget_large` | большой (порог поднят с 220×110) |
| **Эквалайзер** | 40×40 | `blueos_eq_widget_{bars,ring,wave,full}` | 1×1, четыре стиля |
| **Сводка** | 180×40 | summary, «Сэнсэй» отдельной строкой | узкий вариант (патч 0019) |
| | 330×40 | summary, всё в одну строку | широкий вариант |

## 3. Расчёт под 360×800 dp

Размер ячейки сетки 4×5 на экране 360 dp по ширине:
`(360 − 2×8 dp отступы) / 4 ≈ 86 dp` на столбец. Но Launcher3 считает ячейку иначе — с учётом
hotseat, панелей и системных отступов; фактические размеры виджетов покажет только сам телефон:

```
adb shell dumpsys appwidget | grep -A 6 "Widget ID"
```
(в выводе — `size=2x1`, `minWidth`/`minHeight` в dp.)

Ориентировочно по ширине (с учётом 8 dp отступа в каждой ячейке):

| Виджет | Ширина на 4×5, 360 dp | Достижимые макеты |
|---|---|---|
| 1 столбец | ≈ 82 dp | только 1×1 (эквалайзер, батарея 40×40) |
| 2 столбца | ≈ 170 dp | 2×1 и 2×2 (пороги 110 dp пройдены) |
| 3 столбца | ≈ 258 dp | 2×2 |
| 4 столбца | ≈ 346 dp | 2×2 и «широкая полоса» 300×40 — **порог 300 dp достижим** |
| 5 столбцов (сетка 5×6) | ≈ 274 dp | 2×2; широкая полоса **не достижима** |

**Вывод по ширине.** Музыкальный виджет в «широкой полосе» (300 dp) на KM4k помещается только на 4 столбца
сетки 4×5. На сетке 5×6 (4 столбца ≈ 274 dp) он не поместится и система возьмёт 2×2 — это не поломка,
но вид будет не тот, что задумал автор.

**Вывод по высоте.** На 800 dp высоты сетка 4×5 даёт ≈ 145 dp на строку (с отступом 8 dp) — это почти
ровно то, что автор закладывал для 4×5 на Pixel 6a (в патче 0019 сказано: «одна строка — 145,5 dp
на сетке 4×5, 122,7 dp на 5×6»). Значит, **по высоте экрана 4×5 на KM4k подходит почти идеально**,
и двухстрочные макеты (110×160, 300×160) помещаются.

Итог: **сетка 4×5 на KM4k — правильный выбор**, и она уже стоит по умолчанию (патч Launcher3 задаёт
`BLUEOS_DEFAULT_GRID_NAME = "4_by_5"`).

## 4. Что делать, если виджеты выглядят не так

### 4.1 Проверить фактические размеры
```
adb shell dumpsys appwidget | grep -B 2 -A 8 "BlueOS"
```
Смотрите `minWidth`/`minHeight` в dp для каждого виджета и сравнивайте с таблицей порогов выше.

### 4.2 Если макет «не тот»
Значит, фактический размер виджета не пересёк порог. Варианты:

1. **Увеличить виджет на экране** (перетащить маркер) — самый простой путь.
2. **Изменить сетку**: «Обои и стиль»/лаунчер → настройки сетки. 5×6 даст больше узких ячеек по высоте
   (≈122,7 dp на строку, как в комментарии патча 0019), но потеряете «широкую полосу» музыки (300 dp).
3. **Править пороги в образе** (нужна своя сборка — путь B или C). Файлы:
   ```
   frameworks/base/packages/SystemUI/src/com/android/systemui/blueos/widgets/*.kt
   ```
   Например, для экрана 360 dp «широкую полосу» можно опустить до 260 dp:
   ```kotlin
   SizeF(260f, 40f) to R.layout.blueos_media_widget_wide,
   ```
   Не забудьте: порог включает 8 dp отступа, а «Sensay» на отдельной строке включается уже на 180 dp.

### 4.3 Если виджет вообще не появляется
* Проверьте, что виджет добавлен с правильным размером (2×1, 2×2, 4×1).
* `adb logcat -s Launcher3:E AppWidget:E` — покажет ошибки привязки.
* Перезапустите лаунчер: `adb shell am force-stop com.android.launcher3`.

## 5. Сетка и раскладка по умолчанию

BlueOS патчит Launcher3:
* `BLUEOS_DEFAULT_GRID_NAME = "4_by_5"` — сетка по умолчанию;
* `res/xml/default_workspace_4x5.xml` — раскладка рабочего стола для новой прошивки;
* `mono-icons:with-theme` — тема значков по умолчанию.

Если на вашей прошивке сетка по умолчанию другая (5×6), лаунчер возьмёт раскладку LineageOS для неё
(`default_workspace_5x6.xml`), а не BlueOS. Тогда: скопируйте `default_workspace_4x5.xml` в
`default_workspace_5x6.xml` (в дереве `packages/apps/Launcher3/res/xml/`) и поправьте клетки —
либо просто переключите сетку вручную на 4×5 в настройках лаунчера.

---

## 6. Персонаж на экране бллюровки

Положение и размер персонажа задаются долями экрана, поэтому на другом экране он может «поехать».
Если добавлены файлы персонажа и он стоит не там: «Обои и стиль» → «Персонаж» → «Своё место».
Анимация загрузки — кадр 640×336 по центру, подходит любой экран.

---

## 7. Практическая последовательность

1. Поставить GSI (путь A).
2. `adb shell wm density` — уточнить плотность, пересчитать dp.
3. `adb shell dumpsys appwidget` — снять реальные размеры виджетов.
4. Сравнить с таблицей порогов; при несовпадении — подвинуть виджет или переключить сетку.
5. Если нужно точное попадание — собрать образ с изменёнными `SizeF(...)` (путь B).
